# 04 — Matriz de rotas do frontend (web)

> Execução: `next build` forçado (lista oficial de rotas), crawler Playwright autenticado em desktop 1366×900 (`evidence/scripts/crawl.mjs`) e em mobile 375×812 (`crawl_mobile.mjs`), verificação manual no navegador do painel, curl no BFF. Ambiente: `next dev` (porta 3417) contra a API isolada — `next start` não serve o painel com API em `http://` (P1-15).
> Leitura estática por página: `evidence/agent_reports/agent_C_web.md` §3 (arquivo:linha).
> "Usa API real" = consome a API via Server Component, BFF ou `/api/backend` (nenhuma página usa dados de backend simulados, exceto `/dev/calibration`).

## 1. Contagem

- **44 páginas** (`page.tsx`, todas Server Components): 35 backoffice `/app/**`, 5 públicas (`/`, `/login`, `/register`, `/imoveis`, `/imoveis/[slug]`), 2 portais (`/inquilino`, `/proprietario`), 1 dev (`/dev/calibration`), 1 legado (`/dashboard`).
- **7 route handlers** (BFF): `/api/auth/login`, `/api/auth/logout`, `/api/auth/register`, `/api/backend/[...path]`, `/api/leads/[id]/status`, `/api/portal/auth/consume`, `/api/portal/auth/logout`.
- 2 layouts; **não existem** `middleware.ts`, `error.tsx`, `not-found.tsx`, `loading.tsx`. Proteção de `/app/**` é feita no layout (sem sessão → 307 `/login`, PROVADO).
