### Defeitos sistêmicos (causa raiz de vários P1)

1. **`?limit=200` em 37 chamadas, mas a API aceita no máximo 100.** Toda rota de listagem faz `*QuerySchema.parse(request.query)` sobre `paginationQuerySchema` com `limit ... .max(100)` (`packages/contracts/src/common.ts:18-21`). Um `ZodError` vira HTTP 400 (`apps/api/src/errors.ts:29-38`). Resultado: o overview mostra tudo zerado, os selects de imóvel e de candidatura ficam vazios (não dá para criar listing, proposta, vistoria ou contrato) e os nomes não aparecem em cerca de 15 telas.
2. **O BFF força `content-type: application/json` também em mutações sem corpo.** Ver `apps/web/src/lib/api-server.ts:88` e `app/api/backend/[...path]/route.ts:44-48`. No Fastify 5.12.0, métodos com corpo (DELETE, PATCH, PUT, POST) passam pelo parser sempre que há content-type (`fastify.js:140-148` e `lib/handle-request.js:40-86`). Corpo vazio gera `FST_ERR_CTP_EMPTY_JSON_BODY` (`lib/content-type-parser.js:317-321`), que vira 400 (`apps/api/src/errors.ts:48-57`). Isso quebra **logout**, gerar contrato, enviar para assinatura, aprovar template, cancelar e estornar cobrança, processar vistoria, remover membro e remover característica.
3. **Violação das Rules of Hooks.** Há `return` antecipado antes de `useMemo`/`useEffect`. `/app/inspections/[id]` quebra toda vez que carrega. Outras 18 páginas quebram quando a API responde 401 ou 403. Não existe `error.tsx` nem `eslint-plugin-react-hooks` (`eslint.config.mjs:1-38`).
4. **O BFF só trata JSON** (`api-server.ts:100-101`). A exportação CSV baixa um arquivo com o conteúdo `{}`.
5. **O BFF não repassa o IP do cliente** (`api-server.ts:90-94`). A chave de rate limit é `ip:${request.ip}` (`apps/api/src/app.ts:95-98`) e o limite de login/cadastro é 10/min (`apps/api/src/routes/auth.ts:46,125`). Com isso o limite de login vale para **todos os usuários juntos**.

## 5. BFF e segurança

**`app/api/backend/[...path]/route.ts`**

- **Sem allowlist.** Qualquer path da API é alcançável: `segments.map(decodeURIComponent).join('/')` (`:32-34`). `%2F` e `..` são decodificados, então dá para fazer traversal dentro da API. Isso não amplia acesso além do que o próprio proxy já dá (P2-20).
- **Não é SSRF para outro host.** A URL é montada como `${apiBase()}${path}` com `path` sempre começando por `/` (`route.ts:34`, `api-server.ts:95`), então o host fica fixo. NÃO_DETERMINADO: se a API também é exposta publicamente. Se não é, o proxy passa a expor webhooks, `/health/ready` e rotas do portal pela origem do web.
- **CSRF.** A checagem de Origin vale só para não-GET (`route.ts:37-42`; `isSameOrigin` em `api-server.ts:13-17`). O cookie é `SameSite=Lax` e `HttpOnly` (`apps/api/src/plugins/session.ts:42-48`). A proteção depende de os GETs da API não terem efeito colateral. Exceção conhecida: o export grava auditoria (`reporting.ts:357-364`), de impacto baixo (P3-08).
- **Cookies.** Repassa o cookie do browser (`api-server.ts:89`) e devolve `Set-Cookie` (`:102-104`).
- **Content-type e resposta.** Força `content-type: application/json` (`:88`), o que causa o sistêmico 2. Força a resposta para JSON (`:100-101`), o que causa o sistêmico 4. Não tem timeout nem abort (P3-32).
- **XFF.** Não repassa (`:90-94`), o que causa o sistêmico 5. O comentário em `route.ts:8` diz "XFF preservado" e contradiz o código (P3-11).
- **`decodeURIComponent` sem try.** `%` malformado lança `URIError` e gera 500 (P3-09).

**Outros pontos**

- **Route Handlers de auth e portal.** Todos checam Origin. Os que leem corpo usam `await request.json()` sem try (`login/route.ts:12`, `register/route.ts:12`, `consume/route.ts:12`, `leads/[id]/status/route.ts:13`); JSON inválido gera 500 (P3-10).
- **`isSameOrigin`.** Sem `APP_BASE_URL`, compara com `http://localhost:3000` (`api-server.ts:15`), apesar do comentário prometer "fail-fast em produção" (`:10-11`). Em produção sem a variável, todas as mutações recebem 403. Falha fechada (P3-07).
- **`assertSecureApiBase`.** Só é chamado em `app/app/layout.tsx:10`. Em produção com `API_BASE_URL=http://127.0.0.1:4000` (topologia loopback, compatível com `trustProxy: 'loopback'` em `apps/api/src/app.ts:140`), o login funciona, mas `/app` redireciona para `/login` em loop. A configuração real de deploy é NÃO_DETERMINADO (P3-06).
- **`next.config.ts`.** Define X-Frame-Options DENY, nosniff, Referrer-Policy e CSP (`:3-21`). O CSP tem `script-src 'self' 'unsafe-inline' 'unsafe-eval'` (`:11`). Não há HSTS nem Permissions-Policy (P3-05).
- **`lib/session.ts`.** Deriva o role da org ativa, com fallback `viewer` (`:31-35`).
- **`lib/rbac.ts`.** Espelho sem drift em relação a `packages/domain/src/authz/rbac.ts:79-155`: owner e admin com as 35 permissões, agent 27, inspector 12, finance 17, viewer 9. RBAC na UI existe só na navegação e na topbar (`app-shell.tsx:116`, `:129`, `:146`, `:168`, `:306`; `global-search.tsx:65`) e nas queries do overview (`app/app/page.tsx:124-156`). Nenhum botão de ação é condicionado a permissão (P3-04).
- **`middleware.ts` / `proxy.ts`: não existem.** A proteção de `/app/**` está no layout Server (`app/app/layout.tsx:23-34`). Sem sessão, `/auth/me` responde 401 e o layout faz `redirect('/login')`. Layouts são preservados em navegação client-side, então a sessão só é revalidada em navegação completa ou `router.refresh()`. Nesse intervalo, um 401 nas queries vira "Sem acesso" (`use-query.ts:44-45`) ou crash (P2-01).
- **Logout não funciona** (P1-04). Sequência:
  1. `/api/auth/logout` chama `apiProxy` sem corpo (`logout/route.ts:12`).
  2. A API responde 400 antes do handler (`auth.ts:191-212`), então não revoga a sessão nem limpa o cookie.
  3. O cliente ignora o status e navega para `/login` (`account-menu.tsx:19-27`, `app-shell.tsx:471-477`).
  4. O teste de integração usa `app.inject` sem content-type (`tests/integration/src/auth.flow.test.ts:69`), por isso não cobre esse caminho.
- **Rate limit** (P1-06). O limite global de 300/min (`app.ts:150-165`) e o de 10/min para login/register usam `ip:${request.ip}` quando não há autenticação (`app.ts:95-98`). Toda requisição anônima vinda do Next compartilha o IP do servidor Next. O próprio e2e documenta o efeito (`tests/e2e/src/main-journey.spec.ts:311-313`).
